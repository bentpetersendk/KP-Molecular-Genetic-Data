    Read mapping and variant calling¶

    Overview

    Objectives

    • Map single-end and paired-end reads to a reference genome with BWA-MEM and read the main fields of a BAM file (FLAG, POS, MAPQ, CIGAR)
    • Judge a mapping with simple statistics: mapping rate, depth and breadth of coverage
    • Use zero coverage to find reference genes without reads, and explain why that does not prove that a gene is lost
    • Call variants in a haploid bacterial genome with Snippy and explain how the minimum-coverage setting changes the result
    • Call variants in a diploid human genome with bcftools, filter them, and judge the call set with Ts/Tv and genotype counts
    • Explain how low depth affects heterozygous calls, and inspect real and doubtful variants in JBrowse2

    Time: about 3 hours

    Introduction¶

    In the preprocessing practical you cleaned two Illumina datasets. Today you put the clean reads to work. The analysis always has the same three steps:

    1. Mapping. Find where each read comes from in a reference genome. The result is a BAM file: the reads, sorted by their position on the reference.
    2. Looking at the mapping. How many reads mapped, how deep is the coverage, are there regions without reads? This is the quality control of the mapping, and it can already answer biological questions.
    3. Variant calling. At every position, compare the bases in the reads with the reference and decide whether the sample carries a different base: a variant. The result is a VCF file.

    You do this for two genomes that behave very differently:

    Part A: Pseudomonas aeruginosa Part B: human sample HG00418
    Genome about 6.3 Mb, one chromosome about 3,100 Mb; our reads come from chromosome 21
    Ploidy haploid: one copy of each gene diploid: two copies, one from each parent
    Reference PAO1, a laboratory strain first isolated from a wound GRCh38 (hg38), the human reference genome
    Question Which PAO1 genes have no reads, and which mutations does this isolate carry? Which SNPs and small indels does this person carry on chromosome 21?

    The slides for this practical are on the Lectures page.

    Part A: A cystic fibrosis isolate of P. aeruginosa against PAO1¶

    The reads come from a P. aeruginosa isolate that was sampled from the lungs of a Danish patient with cystic fibrosis in 1984. It belongs to a lineage (clone type DK01) that spread between patients and adapted to the human lung over many years. The reads were published by Andersen et al. (2015, PNAS), in the European Nucleotide Archive as run ERR706017; the course file contains the first quarter of that run.

    PAO1 is the standard laboratory strain and has a carefully annotated genome. It is not the ancestor of our isolate: the two are different strains of the same species. Comparing them tells us how much two strains of one species can differ, and it lets us look for changes typical of adaptation to the lung, with limits that you will meet in Step 4 and in Q10.

    Step 1: Predict before you map¶

    Questions: Predict before you map

    Q1. The depth of coverage is the number of reads covering a position, averaged over the genome. Use the FastQC report of Paeruginosa.cut.trim from the preprocessing practical (Total Bases) and the PAO1 genome size (6.26 Mb) to estimate the depth you expect: depth ≈ total sequenced bases / genome size.

    Q2. Do you expect all reads to map to PAO1? Do you expect every PAO1 base to be covered by at least one read? Explain both answers.

    Step 2: Map the reads with BWA-MEM¶

    What happens here. A read is a short string of up to 70 bases; the reference is a string of 6.3 million bases. Comparing every read with every position would take far too long. BWA-MEM first builds an index of the reference: a compact, searchable form of the genome, made once. For each read it looks up short exact matches (seeds) in the index, then extends them into a full alignment that allows a few mismatches and small gaps. It reports the best position of each read, and how sure it is about it.

    Hands-on: Map the reads (takes about a minute)

    1. Map with BWA-MEM (open tool) with the following parameters:
      • "Will you select a reference genome from your history or use a built-in index?": Use a genome from history and build index
      • "Use the following dataset as the reference sequence": PAO1.fasta
      • "Single or Paired-end reads": Single
      • "Select fastq dataset": Paeruginosa.cut.trim
      • Leave everything else as it is ("Set read groups information?": Do not set, "Select analysis mode": 1.Simple Illumina mode, "BAM sorting mode": Sort by chromosomal coordinates).
    2. Rename the output to Pa_vs_PAO1.bam: click the dataset, then the pencil icon, change Name, and click Save.

    Note: The main fields of a BAM record

    A BAM file is the compressed, binary form of a SAM file. Each read has one line with 11 mandatory columns. The ones you need today:

    Column Meaning Example
    QNAME read name HWUSI-EAS656_0037_FC:3:1:16637:1035
    FLAG a number that is the sum of yes/no properties 0 mapped on the forward strand; 16 reverse strand; 4 unmapped; 1024 PCR duplicate
    RNAME, POS reference sequence and leftmost position of the alignment (1-based) NC_002516 104233
    MAPQ mapping quality: how sure the mapper is that this is the right place 60 very sure; 0 the read fits equally well in two or more places
    CIGAR how the read lines up with the reference 70M 70 aligned bases; 40M2D30M 2 reference bases deleted in the read; 20S50M the first 20 bases are not aligned (soft-clipped)

    MAPQ is on the Phred scale, like base qualities: MAPQ 20 means a 1 % chance that the read is placed in the wrong place.

    Hands-on: Look inside the BAM

    1. Click the eye icon of Pa_vs_PAO1.bam. Galaxy shows the first alignments as a table, one read per row.

    Q3. Pick three reads. For each, write down FLAG, POS, MAPQ and CIGAR and say in words what they mean. Decode each FLAG with the SAM flag explainer.

    Step 3: How good is the mapping?¶

    Two numbers summarise a mapping:

    • Mapping rate: the fraction of reads that found a place in the reference. A low rate means that the sample differs from the reference, or is contaminated.
    • Coverage: depth (how many reads cover a position, on average) and breadth (the fraction of the reference covered by at least one read).

    Hands-on: Mapping statistics (each takes less than a minute)

    1. Samtools flagstat (open tool) with "BAM File to report statistics of": Pa_vs_PAO1.bam
    2. Samtools coverage (open tool) with "BAM file": Pa_vs_PAO1.bam (keep the defaults)

    Questions

    Q4. What percentage of the reads mapped to PAO1? Compare with your prediction in Q2. What could the unmapped reads be?

    Q5. In the samtools coverage output, what are the mean depth (meandepth) and the percentage of PAO1 covered by at least one read (coverage)? Does the depth agree with your estimate in Q1? If not, why not?

    Step 4: Which PAO1 genes have no reads?¶

    The idea. If the isolate carries a PAO1 gene, some reads will cover it. If it does not, the gene gets no reads at all. So we look for long stretches of PAO1 with zero coverage and ask which genes lie inside them. This compares gene content without assembling a genome.

    Why strict thresholds. Coverage is never perfectly even. P. aeruginosa DNA is GC-rich, and very GC-rich stretches get fewer reads for technical reasons. A few bases without reads mean nothing. We therefore only count regions with zero coverage over at least 1 kb, and only report a gene if 90 % of it lies in such a region.

    The steps below are all quick table operations:

    1. Genome Coverage writes the depth along the genome as intervals (a bedGraph: sequence, start, end, depth).
    2. Filter keeps the intervals with depth 0.
    3. MergeBED joins zero-depth intervals less than 100 bp apart into one region.
    4. Filter keeps regions of at least 1,000 bp.
    5. Intersect intervals finds the genes that lie (at least 90 %) inside those regions.
    6. Compute adds the length of each region as a fourth column.

    Hands-on: Find regions without reads and the genes inside them

    1. bedtools Genome Coverage (open tool):
      • "Input type": BAM, "BAM file": Pa_vs_PAO1.bam
      • "Output type": BedGraph coverage file
      • "Report regions with zero coverage": Yes
    2. Filter (open tool) on the bedGraph, "With following condition": c4==0
    3. bedtools MergeBED (open tool) on the Filter output, "Maximum distance between features allowed for features to be merged": 100
    4. Filter (open tool) on the MergeBED output, "With following condition": c3-c2>=1000. Rename the output to zero_coverage_regions.bed.
      • "File A to intersect with B": PAO1_genes.bed
      • "File B to intersect with A": zero_coverage_regions.bed
      • "Required overlap": Specify minimum overlap(s), "Minimum overlap required as a fraction of A": 0.9
      • "Write the original A entry once if any overlaps found in B.": Yes

      bedtools Intersect intervals (open tool):

      Rename the output to genes_without_reads.bed.

    6. Compute (open tool) on zero_coverage_regions.bed:

      • Expressions: "Add expression": c3-c2
      • "Mode of the operation": Append

      Rename the output to zero_coverage_regions_interval.bed.

    Note: Reading zero_coverage_regions_interval.bed

    Each line is one region without reads: the sequence name (column 1), the start (column 2), the end (column 3) and, appended by Compute, the length of the region, end minus start (column 4). The largest region is the line with the largest value in column 4.

    BED files count positions from 0, and the end position is not part of the interval. A region written as 1000 1250 covers 250 bases, from position 1,001 to 1,250 in the 1-based numbering that JBrowse2, GenBank and pseudomonas.com use. So end − start is exactly the length, and you add 1 to the BED start to get the first base of a region in JBrowse2.

    To see which genes lie inside a region, compare the start and end of each gene in genes_without_reads.bed (columns 2 and 3) with the start and end of the region.

    Note: What a region without reads does and does not show

    • No reads is not the same as no gene. The isolate may lack the DNA, or carry a version that is too different from PAO1 for its reads to map. Coverage alone cannot tell the two apart.
    • A merged region can contain a few reads. MergeBED joined zero-coverage intervals that were less than 100 bp apart, so a region can include short covered stretches between them.
    • A listed gene can have a few reads. Intersect reports a gene when at least 90 % of it lies inside a region; the rest of the gene may be covered. And because of the merging, not every base inside the region is necessarily without reads.

    Step 5: Find mutations with Snippy (haploid variant calling)¶

    What happens here. A variant caller looks at each position of the reference and at the bases of all reads covering it. If (nearly) all reads show a different base, that is evidence for a variant. Snippy is a small pipeline made for bacteria:

    1. it maps the reads (with BWA-MEM, as in Step 2);
    2. it calls variants with FreeBayes, set to haploid: at each position the bacterium has either the reference base or another base, nothing in between;
    3. it removes weak calls, using thresholds that you can change: the minimum number of reads covering the position (Minimum coverage), the minimum fraction of reads that must show the variant, and minimum mapping and call qualities;
    4. it uses the annotation in PAO1.gbk to say what each variant does to a gene (SnpEff): no change in the protein (synonymous), a different amino acid (missense), a premature stop codon (stop_gained), or a shifted reading frame (frameshift).

    You run Snippy twice: once with the default minimum coverage of 10 reads, and once with 5.

    Hands-on: Run Snippy twice (each takes about a minute)

    1. snippy (open tool):
      • "Will you select a reference genome from your history or use a built-in index?": Use a genome from history and build index
      • "Use the following dataset as the reference sequence": PAO1.gbk
      • "Input type": Single end reads
      • "Select fastq dataset": Paeruginosa.cut.trim
      • "Output selection": keep the ticked outputs, and also tick A summary of the samples and mapping
    2. Run snippy (open tool) again with the same settings, but open Advanced parameters and set "Minimum coverage": 5.
    3. Rename the outputs of the second run so that you can tell them apart, for example snippy mincov5 snps table and snippy mincov5 snps vcf.

    Note: Why the two runs differ

    With "Minimum coverage" 10, Snippy reports a variant only where at least 10 reads cover it. Your mean depth is about 8× (Q5), so most positions have fewer than 10 reads, and every variant there is left out of the default run. Compare VariantTotal in the two summaries: the run with minimum coverage 5 reports many more variants. The default suits deeper data (Snippy was designed for 30× and more). A threshold must fit the depth of your data.

    Hands-on: Build a JBrowse2 view (takes a minute or two)

      • Under Track Category: click Insert Track Category if no category is shown, then add three tracks with Insert Track:
      • "Track Type": BAM Pileups, "BAM Track Data": Pa_vs_PAO1.bam

    Tip: Moving around in JBrowse2

    Type a position such as NC_002516:91,931..92,297 (part of the gene icmF1, PA0077) in the location box and press Enter. Zoom with the magnifying glasses. In the read track, grey means that the read matches the reference; a coloured base is a mismatch.

    • A column in which (nearly) all reads show the same coloured base supports a variant at that position. It does not prove one: reads placed in the wrong copy of a repeat can also line up a mismatch.
    • A single coloured base in one read is often a sequencing error, but not necessarily: at low depth a real variant may be seen in only one or two reads.

    Click a read or a variant to see its details. The sequence is called NC_002516 in all these files.

    Part B: Human chromosome 21¶

    Humans are diploid. At each position a person has one of three genotypes:

    Genotype VCF code Expected fraction of reads with the alternative base
    homozygous reference 0/0 ~0 % (not written to a variant-only VCF)
    heterozygous 0/1 ~50 %
    homozygous alternative 1/1 ~100 %

    The caller has to tell these three apart from a limited number of reads. A heterozygous site seen in only 3 reads may by chance show 3 alternative reads and look like 1/1, or 3 reference reads and look like 0/0. Depth therefore matters much more here than in a haploid bacterium.

    The data. HG00418 is a man from the 1000 Genomes Project (Southern Han Chinese, CHS). His genome was sequenced at high coverage on many sequencing lanes. Our files contain the read pairs of one lane that mapped to chromosome 21 in an earlier analysis.

    Step 7: Map the read pairs to the human genome¶

    The reads are paired: the two reads of a pair come from the two ends of one DNA fragment of a few hundred bases. The mapper uses this: if one read falls in a repeat, its mate can anchor it. Pairs at the expected distance and orientation are flagged properly paired.

    We use Galaxy's built-in index of the human genome (hg38), so no index has to be built. Read groups label every read with its sample; the variant caller uses the sample name (SM) as the name of the sample column in the VCF.

    Step 8: Mapping statistics, duplicates and depth¶

    PCR duplicates. Library preparation includes PCR, which copies DNA fragments. Several read pairs can therefore come from the same original molecule. They are not independent evidence: an error made in an early PCR cycle appears in all copies and can look like a well-supported variant. Duplicates are recognised because both ends of the fragment start at exactly the same positions. MarkDuplicates flags them (FLAG 1024), and the variant caller ignores flagged reads.

    Hands-on: Statistics, duplicates and depth (each takes about a minute)

    1. Samtools flagstat (open tool) on HG00418.bam.
    2. Samtools idxstats (open tool) on HG00418.bam. The output lists, per reference sequence, its length (column 2) and the number of mapped reads (column 3).
    3. MarkDuplicates (open tool) with "Select SAM/BAM dataset or dataset collection": HG00418.bam (keep the defaults: duplicates are flagged, not removed). Rename the BAM output to HG00418.md.bam.
    4. Samtools coverage (open tool) with "BAM file": HG00418.md.bam, and under Additional Options "Show specified region": chr21.

    Step 9: Call variants with bcftools¶

    Variant calling is done in two steps:

    1. bcftools mpileup goes along chr21 and, at each position, collects the bases of all reads covering it (a pileup). It skips reads with low mapping quality (we set MAPQ < 20: we are not sure where they belong), bases with low base quality (< 20: probably sequencing errors) and reads flagged as duplicates. For each position it computes how likely the data are under each genotype (0/0, 0/1, 1/1): the genotype likelihoods.
    2. bcftools call turns those likelihoods into a decision: is there a variant, and which genotype is most likely? It writes only the variant sites. QUAL says how confident the call is that the site is variant (Phred scale: QUAL 20 means a 1 in 100 chance that it is not).

    Hands-on: Pileup and call (takes a few minutes)

    1. bcftools mpileup (open tool):
      • "Alignment Inputs": Single BAM/CRAM, "Input BAM/CRAM": HG00418.md.bam
      • "Choose the source for the reference genome": Locally cached, "Select reference genome": Human Dec. 2013 (GRCh38/hg38) (hg38)
      • Input Filtering Options: "Quality Options": Set base and mapping quality options
      • "Minimum mapping quality for an alignment to be used": 20
      • "Minimum base quality for a base to be considered": 20
      • Restrict to: "Regions": Specify one or more Region(s) directly, "Region chromosome": chr21 (leave start and end empty)
      • Output options: "Optional tags to output": tick DP and AD
      • "output_type" (the last field, just above Additional Options; it has no other label): uncompressed VCF instead of the default compressed BCF
    2. bcftools call (open tool) on the mpileup output:
      • Consensus/variant calling Options: "Calling method": Multiallelic and rare-variant caller
      • Input/output Options: "Output variant sites only": Yes
      • "output_type" (the last field): uncompressed VCF

    Note: Reading a VCF line

    ##CHROM POS ID REF ALT QUAL FILTER INFO FORMAT HG00418
chr21 10414881 . C T 124 . DP=9;... GT:PL:DP:AD 0/1:157,0,98:9:4,5

    Position 10,414,881 has C in the reference and T in this person. QUAL 124: the caller is very sure that there is a variant. In the sample column, read the values in the order given by FORMAT: genotype 0/1 (heterozygous), the genotype likelihoods PL, depth DP 9, and allele depths AD: 4 reads with the reference base and 5 with the alternative base. (An illustration, not a line from your file.)

    Step 10: Filter the calls and judge their quality¶

    Why filter. The raw VCF contains every site where the caller saw some evidence. Many are false: sequencing errors, misplaced reads. Two simple filters remove most of them:

    • QUAL ≥ 20: drop calls the caller itself is unsure about.
    • A depth window: drop sites with very few reads (too little evidence) and sites with far more reads than usual. Unusually high depth usually means reads from two or more similar copies of a sequence piled up in one place, a classic source of false heterozygous calls. With about 5× in the mappable part of chr21, we keep sites with 3 to 15 reads.

    How to judge a call set without knowing the truth: Ts/Tv. There are two kinds of SNPs. Transitions (Ts) exchange a purine for a purine or a pyrimidine for a pyrimidine (A↔G, C↔T); transversions (Tv) are all other changes. There are twice as many possible transversions as transitions, so random errors give Ts/Tv ≈ 0.5. Real human SNPs are biased toward transitions (mainly because methylated C often mutates to T), and genome-wide Ts/Tv is about 2.0–2.1. The closer to 2, the cleaner the call set.

    Hands-on: Filter and summarise (each takes less than a minute)

      • Restrict to: "Include": QUAL>=20 && INFO/DP>=3 && INFO/DP<=15
      • "output_type" (the last field): uncompressed VCF

      bcftools filter (open tool) on HG00418.chr21.raw.vcf:

      Rename the output to HG00418.chr21.filtered.vcf.

    2. bcftools stats (open tool) on the raw VCF, with Restrict to "Samples": HG00418 (this adds the per-sample section PSC).

    3. The same for the filtered VCF.
