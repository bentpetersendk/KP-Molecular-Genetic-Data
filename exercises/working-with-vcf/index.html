    Working with VCF files¶

    Overview

    Objectives

    • Explain the structure of a VCF file: meta-information, header line, fixed columns, INFO, FORMAT and genotypes
    • Count variants, SNPs, Ts/Tv and genotypes in a VCF file with grep, cut, awk, sort and uniq
    • Index, view, query and normalise VCF files with bcftools, and explain why normalisation is needed before comparing
    • Compare your calls with an independent high-coverage call set inside callable regions, and compute precision, recall and genotype concordance
    • Explain why a population call set is not automatically a truth set
    • Compute allele frequencies per population, distinguish them from genotype frequencies, and interpret a PCA of population structure with care

    Time: about 3 hours

    Introduction¶

    Variant calling produces a VCF file. That is where the analysis starts: we want to know how good the calls are and what they tell us about the person and about human variation. In this practical you will:

    1. take the HG00418 calls of the previous practical apart with the Unix commands you already know (a VCF file is a text table);
    2. learn bcftools, the standard toolbox for VCF files;
    3. compare the calls with an independent, much deeper call set for the same person, and measure how many of the calls are confirmed and how many variants were missed;
    4. use the genotypes of 2,505 people from 26 populations to compute allele frequencies and look at population structure.

    You work in a terminal in Galaxy Europe, as in the Unix practical. The slides for this practical are on the Lectures page.

    Data. The shared history for this practical contains:

    Dataset What it is
    HG00418.chr21.calls.vcf.gz the filtered HG00418 calls on chromosome 21 from the previous practical (bcftools, about 5× depth)
    HG00418.chr21.highcov.vcf.gz the variants of HG00418 on chromosome 21 from an independent, deep data set: the 1000 Genomes high-coverage release (about 30×, Illumina NovaSeq, GATK, only calls that passed its quality filter)
    HG00418.callable.bed the parts of chr21 where the reads of the previous practical had a depth of 3 to 15 (mapping and base quality at least 20): where we could call variants
    chr21.fa the sequence of chromosome 21 (GRCh38)
    panel.chr21.vcf.gz genotypes of 2,505 people at common SNPs on chr21: the 2,504 unrelated people of the 1000 Genomes Project plus HG00418
    samples_pop.tsv person, population and super-population of everyone in the panel
    pca.py Python code for the PCA in Part 5

    Part 0: Start the terminal and get the data¶

    Hands-on: Terminal and data

    1. Open the shared data history, click Import this history and name the copy VCF practical.
    2. Start Interactive JupyterLab Notebook from this history and open a terminal, exactly as in the Unix practical (search the tool, Run Tool, open it from Interactive Tools, then File → New → Terminal).

    3. Make a working directory and fetch the data:

      mkdir -p ~/vcf-practical && cd ~/vcf-practical
for f in HG00418.chr21.calls.vcf.gz HG00418.chr21.highcov.vcf.gz HG00418.callable.bed chr21.fa panel.chr21.vcf.gz samples_pop.tsv pca.py; do
    get -i "$f" -t name && cp "/import/$f" .
done
ls -l

    4. Open a second terminal (File → New → Terminal) and install bcftools and Python's plotting library there. It takes about a minute; continue with Part 1 in the first terminal meanwhile:

      mamba create -y -n vcf -c conda-forge -c bioconda bcftools=1.24 numpy pandas matplotlib-base

    5. When the installation has finished, make the new tools available in each terminal you use:

      conda activate vcf
bcftools --version | head -n 1

    Tip: If something goes wrong

    • get works once per file and session. Running it again for the same file prints a Python error ending in KeyError: 'extension'; the file is already in /import, so just copy it.
    • Every file you make lives only as long as this JupyterLab. If you stop it, start again with the commands above (and conda activate vcf after a new installation).
    • bcftools prints warnings such as [W::bcf_hdr_check_sanity] MQ should be declared as Type=Float for the calls file. They concern the header text and can be ignored.

    Part 1: A VCF file is text¶

    A VCF file has three parts:

    1. Meta-information lines, starting with ##. They describe the file: the reference genome, the chromosomes and their lengths, the filters, and every field that can appear in the INFO and FORMAT columns.
    2. One header line, starting with #CHROM: the column names.
    3. One line per variant. Eight fixed columns (CHROM, POS, ID, REF, ALT, QUAL, FILTER, INFO), then FORMAT, then one column per sample.

    The file is compressed, so we read it with zcat instead of cat.

    Hands-on: Look at the file

    zcat HG00418.chr21.calls.vcf.gz | head -n 5
zcat HG00418.chr21.calls.vcf.gz | grep -c '^##'
zcat HG00418.chr21.calls.vcf.gz | grep '^##' | cut -d= -f1 | sort | uniq -c
zcat HG00418.chr21.calls.vcf.gz | grep '^##INFO' | head -n 5
zcat HG00418.chr21.calls.vcf.gz | grep '^#CHROM'
zcat HG00418.chr21.calls.vcf.gz | grep -v '^#' | head -n 3

    Questions

    Q1. How many meta-information lines are there, and which kind is most common? Which lines tell you which reference genome was used? What are the ten column names?

    Q2. Write one pipeline that counts the variants in the file.

    SNPs and indels¶

    A SNP has a single base in REF and a single base in ALT. An indel has REF and ALT of different lengths: AT → A is a deletion of T, A → AT an insertion. awk can test this: it splits each line into columns $1, $2, …, and length($4) is the length of REF.

    Hands-on: Count SNPs and other variants

    zcat HG00418.chr21.calls.vcf.gz | grep -v '^#' \
  | awk -F'\t' '{ if (length($4)==1 && length($5)==1) snp++; else other++ }
                END { print "SNPs:", snp, " other:", other }'
zcat HG00418.chr21.calls.vcf.gz | grep -v '^#' | awk -F'\t' '$5 ~ /,/' | wc -l
zcat HG00418.chr21.calls.vcf.gz | grep -v '^#' | awk -F'\t' '$5 ~ /,/' | head -n 3 | cut -f1-5,10

    Questions

    Q3. How many SNPs and other variants does the awk command count? The last two commands find lines where ALT contains a comma. What does such a line mean, and why does it fool our simple SNP test?

    Transitions and transversions¶

    In the previous practical, bcftools stats reported Ts/Tv. Now compute it yourself: a transition is A↔G or C↔T, everything else is a transversion.

    Hands-on: Compute Ts/Tv for both call sets

    for f in HG00418.chr21.calls.vcf.gz HG00418.chr21.highcov.vcf.gz; do
  zcat $f | grep -v '^#' \
    | awk -F'\t' 'length($4)==1 && length($5)==1 { c = $4 $5
          if (c=="AG" || c=="GA" || c=="CT" || c=="TC") ts++; else tv++ }
          END { print "Ts:", ts, " Tv:", tv, " Ts/Tv:", ts/tv }'
done

    Questions

    Q4. What is Ts/Tv for our calls and for the high-coverage calls? Real human SNPs give about 2.0–2.1 and random errors about 0.5. What do the two values tell you, and what can Ts/Tv not tell you?

    Genotypes¶

    The sample column holds several values separated by :, in the order given by FORMAT. The genotype (GT) is always first. 0 is the reference allele, 1 the first ALT allele, 2 the second, and so on.

    Hands-on: Count genotypes

    zcat HG00418.chr21.calls.vcf.gz | grep -v '^#' | cut -f10 | cut -d: -f1 | sort | uniq -c
zcat HG00418.chr21.highcov.vcf.gz | grep -v '^#' | cut -f10 | cut -d: -f1 | sort | uniq -c
zcat panel.chr21.vcf.gz | grep -v '^#' | head -n 1 | cut -f1-14

    Questions

    Q5. How many heterozygous (0/1) and homozygous alternative (1/1) genotypes are in our calls and in the high-coverage calls? Compare the ratio of the two in each set. What does 1/2 mean?

    Q6. The last command shows the first line of the population panel. Its genotypes are written 0|1 and 1|0 instead of 0/1. What is the difference between / and |?

    Part 2: bcftools¶

    Unix tools treat a VCF file as plain text, so you have to keep track of columns yourself. bcftools understands the VCF structure: you can ask for fields by name, select a region, or filter on genotype. It needs the file to be compressed with bgzip (the .vcf.gz files here are) and indexed: the index (.csi file) records where each part of the chromosome lies in the file, so bcftools can jump straight to a region instead of reading everything.

    Hands-on: Index, view and query

    In a terminal where you ran conda activate vcf:

    bcftools --version | head -n 1
for f in HG00418.chr21.calls.vcf.gz HG00418.chr21.highcov.vcf.gz panel.chr21.vcf.gz; do
    bcftools index -f "$f"
done
ls *.csi
bcftools view -h HG00418.chr21.calls.vcf.gz | tail -n 1 # header line only
bcftools view -H HG00418.chr21.calls.vcf.gz | head -n 3 # variant lines only
bcftools view -H -r chr21:30000000-30100000 HG00418.chr21.calls.vcf.gz | wc -l
bcftools query -f '%CHROM\t%POS\t%REF\t%ALT\t%QUAL[\t%GT\t%DP]\n' HG00418.chr21.calls.vcf.gz | head -n 3

    In bcftools query -f, %POS prints a column, [...] repeats its content for every sample, and \t and \n are a tab and a new line.

    Questions

    Q7. How many variants are in the 100 kb window chr21:30000000-30100000?

    Q8. Print the five heterozygous SNPs with the lowest sample depth (FORMAT/DP), with their position, alleles, QUAL, DP and AD. (Hint: bcftools view -g het -v snps keeps heterozygous SNPs; then bcftools query, sort on the DP column and head.) The filter of the previous practical required INFO/DP>=3: how can a call have a lower DP here? Would you trust these calls?

    Normalisation: write each variant one way¶

    Before two VCF files can be compared, the same variant must be written the same way in both. Two things can differ:

    • Multiallelic sites. One line G → A,C, or two lines G → A and G → C. -m -any splits them into one line per alternative allele.
    • Indels in repeats. Deleting one A from CAAAAG gives the same sequence whichever A is deleted, so the deletion can be written at four positions. The convention is the leftmost. -f chr21.fa lets bcftools check the reference sequence, trim unneeded bases and shift indels to the left.

    Hands-on: Normalise both call sets

    for s in calls highcov; do
    bcftools norm -f chr21.fa -m -any HG00418.chr21.$s.vcf.gz -Oz -o $s.norm.vcf.gz
    bcftools index -f $s.norm.vcf.gz
done

    For each file bcftools prints a line Lines total/split/joined/realigned/....

    Questions

    Q9. How many lines did bcftools split and how many did it realign, in each file? Why do the two files differ so much?

    Part 3: How good are the calls?¶

    We now compare our calls with the high-coverage calls for the same person. Every variant ends up in one of three groups:

    in the high-coverage calls not in the high-coverage calls
    in our calls confirmed (true positive, TP) not confirmed (false positive, FP)
    not in our calls missed (false negative, FN) (not counted)

    From these we compute:

    • Precision = TP / (TP + FP): of the variants we reported, what fraction is confirmed?
    • Recall (sensitivity) = TP / (TP + FN): of the variants in the high-coverage set, what fraction did we find?

    We only compare inside HG00418.callable.bed. Where we had no reads we could not find anything, and counting those sites would measure how much of chr21 our reads covered, not how well variants were called.

    Hands-on: Compare with bcftools isec

    bcftools isec (intersect) splits two VCF files into variants found only in the first, only in the second, and in both:

    bcftools isec -R HG00418.callable.bed -p isec calls.norm.vcf.gz highcov.norm.vcf.gz
cat isec/README.txt
for i in 0 1 2 3; do echo "isec/000$i.vcf: $(grep -vc '^#' isec/000$i.vcf)"; done

    Questions

    Q10. Using isec/README.txt, which file holds the confirmed calls, which the unconfirmed calls and which the missed variants? How many are in each?

    Q11. Compute precision and recall, for example awk 'BEGIN { print TP/(TP+FP) }' with your numbers filled in. Then do the same for SNPs and indels separately: make SNP-only and indel-only versions of both normalised files (bcftools view -v snps or -v indels, -Oz -o, then bcftools index), and run isec on each pair with its own -p directory. Which type of variant do we call better?

    Genotype concordance¶

    A variant can be in both files with a different genotype, for example 1/1 in ours and 0/1 in the high-coverage set. Genotype concordance is the fraction of shared variants with the same genotype.

    The commands below make a two-column table per file (variant, genotype), write phased genotypes like unphased ones (1|0 → 0/1), and join the two tables on the variant:

    Hands-on: Genotype concordance

    gt() {
  bcftools query -R HG00418.callable.bed -f '%CHROM:%POS:%REF:%ALT\t[%GT]\n' "$1" \
  | awk -F'\t' '{ g=$2; gsub(/\|/,"/",g); split(g,a,"/");
                  if (a[1]>a[2]) g=a[2]"/"a[1]; print $1"\t"g }' | sort -k1,1
}
gt calls.norm.vcf.gz > calls.gt
gt highcov.norm.vcf.gz > highcov.gt
join -t $'\t' calls.gt highcov.gt > shared.gt
head -n 3 shared.gt
awk -F'\t' '{ n++; if ($2==$3) ok++; else bad["ours " $2 " / high coverage " $3]++ }
            END { print "shared:", n, " concordance:", ok/n;
                  for (k in bad) print bad[k], k }' shared.gt

    gt() defines a small shell function, so the same pipeline can be run on both files.

    Questions

    Q12. What is the genotype concordance? Which disagreement is most common? Explain it with what you know about depth and heterozygous sites.

    Q13. We have called the high-coverage set our yardstick. Is it the truth? Give one reason why some of our "unconfirmed" calls could be real, and one why some "missed" variants could be wrong. What would a proper benchmark for this person need?

    Part 4: HG00418 among human populations (Optional)¶

    The 1000 Genomes Project sequenced people from 26 populations, grouped into five super-populations: African (AFR), admixed American (AMR), East Asian (EAS), European (EUR) and South Asian (SAS). The panel contains the 2,504 people of the project's unrelated set, plus HG00418 (his partner is in the unrelated set, his child is not). Relatives are left out so that no family is counted twice.

    Hands-on: Who is in the panel?

    head -n 3 samples_pop.tsv
tail -n +2 samples_pop.tsv | cut -f3 | sort | uniq -c
grep -w HG00418 samples_pop.tsv
bcftools query -l panel.chr21.vcf.gz | wc -l # people
bcftools view -H panel.chr21.vcf.gz | wc -l # SNPs

    Allele frequencies¶

    The allele frequency (AF) of a SNP in a group is the fraction of all chromosome copies in that group that carry the alternative allele. Each person has two copies, so for n people: AF = (number of alternative alleles) / (2n). A genotype 0/1 adds 1 alternative allele, 1/1 adds 2.

    bcftools +fill-tags computes AF for every group listed in a file of person and group, and adds the values to the INFO column as AF_AFR, AF_EAS, and so on. We leave HG00418 out of the groups, so that he does not count towards the frequencies we compare him with.

    Hands-on: Allele frequencies per super-population

    grep -v -w HG00418 samples_pop.tsv | tail -n +2 | cut -f1,3 > superpop.txt
bcftools +fill-tags panel.chr21.vcf.gz -Oz -o panel.af.vcf.gz -- -S superpop.txt -t AF
bcftools index -f panel.af.vcf.gz
bcftools view -h panel.af.vcf.gz | grep '^##INFO=<ID=AF'
bcftools query -f '%POS\t%REF\t%ALT\t%AF_AFR\t%AF_EAS\t%AF_EUR\n' panel.af.vcf.gz > af.tsv
head -n 3 af.tsv

    bcftools warns that the list has one person fewer than the VCF file: that is HG00418, left out on purpose.

    Questions

    Q14. How many people and how many SNPs are in the panel? How many people per super-population? To which population and super-population does HG00418 belong?

    Q15. A SNP is common in a group if the minor allele has a frequency of at least 5 %, that is 0.05 ≤ AF ≤ 0.95. How many SNPs are common in AFR, in EAS and in EUR? (For AFR: awk -F'\t' '$4>=0.05 && $4<=0.95' af.tsv | wc -l.) Which group has the most common SNPs? Is that what you expect from human history?

    Hands-on: Find the SNPs that differ most between EAS and EUR

    awk -F'\t' '{ d=$5-$6; if (d<0) d=-d; print $0"\t"d }' af.tsv | sort -t$'\t' -k7,7gr -k1,1n | head -n 5

    Then look up the HG00418 genotype at each of the five positions (replace POS by the position, without commas):

    bcftools query -s HG00418 -r chr21:POS -f '[%GT]\n' panel.chr21.vcf.gz

    Questions

    Q16. Which five SNPs differ most in AF between EAS and EUR, and in which direction? Look up one of them in the Ensembl genome browser (change the position in the address to the SNP's position). Does it have an rsID? Is it in or near a gene?

    Q17. What are HG00418's genotypes at these five SNPs? Does he carry the allele that is more common in EAS every time?

    grep -w EAS superpop.txt | cut -f1 > eas.txt
bcftools query -S eas.txt -r chr21:POS -f '[%GT\n]' panel.chr21.vcf.gz | sort | uniq -c

    Part 5: A PCA of population structure (Optional)¶

    The idea. Each person has a genotype at thousands of SNPs: far too many numbers to look at. A principal component analysis (PCA) finds the few directions in which people differ most, and gives each person a coordinate on them (PC1, PC2, …). People with similar genotypes get similar coordinates. Plotting PC1 against PC2 shows groups of similar people without telling the method which population anyone belongs to.

    Common SNPs only. Very rare SNPs say little about groups and add noise, so we keep SNPs with a minor allele frequency of at least 5 % in the whole panel.

    Why prune. SNPs close to each other are inherited together and are therefore correlated (linkage disequilibrium, LD). A block of correlated SNPs would count many times and could dominate the PCA. bcftools +prune removes SNPs that are strongly correlated (r² > 0.2) with another SNP within 50 kb.

    Hands-on: Filter, prune and export the genotypes (takes a few minutes)

    bcftools view -q 0.05:minor panel.chr21.vcf.gz -Oz -o common.vcf.gz
bcftools index -f common.vcf.gz
bcftools index -n common.vcf.gz
bcftools +prune -m 0.2 -w 50kb common.vcf.gz -Oz -o pruned.vcf.gz
bcftools view -H pruned.vcf.gz | wc -l
bcftools query -l pruned.vcf.gz > samples.txt
bcftools query -f '[%GT\t]\n' pruned.vcf.gz \
  | sed -e 's/0[|/]0/0/g' -e 's/0[|/]1/1/g' -e 's/1[|/]0/1/g' -e 's/1[|/]1/2/g' -e 's/\.[|/]\./NA/g' \
  > genotypes.tsv
head -n 2 genotypes.tsv | cut -f1-10

    genotypes.tsv has one row per SNP and one column per person: the number of alternative alleles (0, 1 or 2).

    Hands-on: Run the PCA

    python pca.py
grep -w HG00418 pca.tsv

    The script scales each SNP, computes the PCA and writes pca.png (PC1 against PC2, coloured by super-population, HG00418 circled) and pca.tsv (the coordinates). Open pca.png from the JupyterLab file browser (folder vcf-practical). It takes about 20 seconds.

    Questions

    Q19. How many SNPs are common in the panel, and how many are left after pruning? What would happen to the PCA without pruning?

    Q20. Look at pca.png. Which super-population is separated from the others along PC1, and which along PC2? Where is HG00418? What fraction of the variation do PC1 and PC2 explain?

    Q21. Give two reasons to be careful when interpreting such a plot. Why would a PCA of the whole genome separate the groups more clearly than one chromosome?
