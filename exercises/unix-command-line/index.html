    The Unix command line¶

    Overview

    Objectives

    • Open a Unix terminal in Galaxy Europe and find out where you are in the file system
    • Create, copy, move and delete files and directories, using relative and absolute paths
    • Inspect a table and a FASTA file with head, tail, less and wc
    • Select columns with cut, combine them with paste, and sort text and numbers with sort
    • Count identical lines with sort and uniq
    • Search text with grep and simple patterns
    • Save output with > and >>, and connect commands with pipes (|)
    • Answer a biological question with a pipeline that you compose yourself

    Time: about 3 hours

    Introduction¶

    Most molecular genetic data are plain text: sequence files (FASTA, FASTQ), alignments (SAM), variant files (VCF), annotation tables and the result tables of almost every analysis tool. The Unix command line gives you small, fast programs that each do one thing with text: show the first lines, count lines, pick out columns, sort, or search. Connected to each other, they answer real questions about data in seconds, and the same commands work on your laptop, on a Galaxy server and on a large compute cluster.

    In this practical you work in a real Unix terminal inside Galaxy Europe. You will:

    • find your way around the file system;
    • create, copy, move and delete files and directories;
    • inspect a protein table and a FASTA file;
    • cut, sort, count and search them;
    • connect commands with pipes to answer a biological question.

    The slides for this practical are on the Lectures page.

    Data. You will work with two files exported from UniProtKB/Swiss-Prot, the manually reviewed part of the UniProt protein database:

    • proteins.tsv: a table of protein entries for a panel of well-known human disease genes (such as TP53, BRCA1, CFTR and HBB) and the corresponding proteins in other vertebrates;
    • proteins.fasta: the amino-acid sequences of the same proteins.

    Get a terminal in Galaxy¶

    You need a registered Galaxy Europe account for this practical: the terminal runs in an Interactive Tool, and Galaxy Europe starts Interactive Tools only for users who are logged in.

    Step 1 — Import the data history¶

    Hands-on: Import the data

    1. Log in to Galaxy Europe (create a free account first if you do not have one). Log in before you open the data link: otherwise your copy is not saved in your account.
    2. Open the shared data history: shared data history
    3. Click Import this history (top right, above the history).
    4. In the Copying History dialog:
      • "Enter a title for the new history": replace the suggested title with Unix practical
      • keep Copy only the active, non-deleted datasets. selected
      • click Copy History.
    5. A blue message confirms "History imported and is now your active history", but the page still shows the shared history. Click the Galaxy logo at the top left (Home) to return to the main page. Your copy Unix practical is now shown in the history panel on the right. If the panel shows another history, open Histories in the left-hand activity bar and switch to Unix practical.
    6. Check that the history contains the two datasets proteins.tsv and proteins.fasta.

    Step 2 — Start JupyterLab¶

    JupyterLab is a web-based working environment. Galaxy Europe runs it for you as an Interactive Tool, and it includes a Unix terminal.

    Hands-on: Start the JupyterLab Interactive Tool

    1. Check that Unix practical is your current history (history panel on the right). JupyterLab can only fetch data from the history it was started from.
    2. Click Tools in the activity bar, type JupyterLab in the tool search box, and click Interactive JupyterLab Notebook.
    3. Keep the setting "Do you already have a notebook?" at Start with a fresh notebook, and click Run Tool.
    4. Galaxy shows "Waiting for InteractiveTool result view(s) to become available", and three new items appear in your history: JupyTool output collection, Executed JupyTool Notebook and Interactive JupyterLab Notebook. They do not turn green while JupyterLab is running. This is normal.
    5. Click Interactive Tools in the activity bar. Under Active Interactive Tools you see JupyTool interactive tool with the status Running. This usually takes less than a minute. If it is still not listed as Running after five minutes, click Run Tool again (step 3), and tell a teacher if that does not help either.
    6. Click the ↗ icon (Open in new tab) next to it. JupyterLab opens in a new browser tab. (Clicking the name itself opens JupyterLab inside the Galaxy page, where it has less room.)

    Warning: Not logged in?

    If you start the tool without being logged in, Galaxy still shows a green message, but the new history items turn red and no Interactive Tool appears. Log in, import the data history again, and start the tool again.

    Step 3 — Open a terminal¶

    Hands-on: Open a terminal in JupyterLab

    1. In JupyterLab, click File → New → Terminal. (You can also click the Terminal tile in the Launcher, under Other.) If JupyterLab asks "Would you like to get notified about official Jupyter news?", click No.

    2. A terminal tab opens with a line like this, followed by a blinking cursor:

      (base) jovyan@4aa74bb55da1:/data/jwd07/pulsar_staging/113469050/working/jupyter$

      This is the prompt. It shows your user name (jovyan), the name of the computer (a random code) and the directory you are in, and it ends with $. The shell is waiting for a command. (base) is the name of a software environment; you can ignore it.

    Tip: Typing, pasting and stopping

    • Type a command and press Enter to run it. Commands, options and file names are case-sensitive, and the spaces between them matter.
    • Type the commands yourself where you can: that is how you learn them. To paste a command, right-click → Paste in the terminal (on a Mac, Cmd+V also works). Copy text from the terminal by selecting it and choosing right-click → Copy.
    • Ctrl+C in the terminal does not copy. It stops the command that is running and gives you a new prompt. Use it whenever the terminal seems stuck, for example after an unfinished quote (the prompt changes to >).
    • Press Tab to complete a file or command name, and the up arrow to get your previous commands back.

    Warning: This terminal is temporary

    Your terminal runs in a temporary environment that exists only while the Interactive Tool is running.

    • Closing the browser tab, or the terminal tab, does not stop it: reopen it from Interactive Tools in Galaxy. In JupyterLab, File → New → Terminal gives you a new terminal in the same environment, with your files still there.
    • When the tool is stopped (the red square in Interactive Tools, or File → Shut Down in JupyterLab), every file you made in the terminal is deleted. The red square stops the tool at once, without asking. Only the files you send to your Galaxy history with put (see the end of the practical) are kept.

    Do the practical in one sitting if you can. If you have to start again, the tip Starting again at the end of Part 1 gets you back to work in a minute.

    Part 1 — Where am I?¶

    Every command line has the same parts: the command (the program to run), then options that change what it does (usually starting with -), then arguments (usually the files it works on), all separated by spaces. In ls -l /import the command is ls, the option is -l and the argument is /import.

    The files on a Unix computer are organised in a tree of directories (folders). The top of the tree is /, the root. You are always in one directory, the current working directory.

    Hands-on: Look around

    1. Print the current working directory:

      pwd

    2. Go to your home directory with cd (change directory) without an argument, and print the working directory again:

      cd
pwd

    3. List the contents of the directory, first briefly and then in the long format:

      ls
ls -l

    Questions

    Q1. What does pwd print right after you open the terminal, and what does it print after cd? Which of the two is your home directory?

    Make a working directory and get the data¶

    Hands-on: Create a directory for this practical

    1. Make a new directory, move into it, and check where you are:

      mkdir unix-practical
cd unix-practical
pwd

    2. Fetch the two data files from your Galaxy history with the command get. It is not a standard Unix command: this Galaxy environment provides it, and it copies a dataset from the history JupyterLab was started from. Each get prints where it saved the file:

      get -i proteins.tsv -t name
get -i proteins.fasta -t name

      Run each get only once. If you run it again for the same file, it prints a long error message that ends with KeyError: 'extension'. The file is still there: continue with the next step.

    3. get saves the files in the directory /import. Look at them there, then copy both to your current directory, and list it:

      ls -l /import
cp /import/proteins.tsv /import/proteins.fasta .
ls -l

    Note: Absolute and relative paths

    A path says where a file is. A path that starts with / is absolute: it starts at the root, and it means the same thing wherever you are. Any other path is relative: it starts in your current directory. Three short names are useful:

    • . means "the current directory";
    • .. means "the directory one level up";
    • ~ means "my home directory".

    Questions

    Q2. Is /import/proteins.tsv an absolute or a relative path? What does the . at the end of the cp command stand for? Write the absolute path of your own copy of proteins.tsv.

    Tip: Starting again

    If your Interactive Tool was stopped, start JupyterLab again from Unix practical (Step 2), open a terminal (Step 3), and run:

    mkdir -p ~/unix-practical
cd ~/unix-practical
get -i proteins.tsv -t name
get -i proteins.fasta -t name
cp /import/proteins.tsv /import/proteins.fasta .

    If you had already reached Part 4, also repeat its first step (tail -n +2 …).

    Part 2 — Files and directories¶

    Hands-on: Copy and compare

    1. Make a copy of the table, and compare the copy with the original using diff:

      cp proteins.tsv backup.tsv
ls
diff proteins.tsv backup.tsv

    Questions

    Q3. What does diff print, and what does that tell you about the two files?

    Hands-on: Overwrite a file (on purpose)

    1. Now copy the FASTA file onto backup.tsv, and look at the first three lines of backup.tsv:

      cp proteins.fasta backup.tsv
head -n 3 backup.tsv

    Questions

    Q4. What is in backup.tsv now? Did cp warn you before it replaced the old contents?

    Warning: No undo, no trash bin

    cp and mv replace an existing file with the same name without asking, and so does > (Part 4). rm deletes a file permanently: there is no trash bin to restore it from, here or on any other Unix system. Before you replace or delete something, check what it is (ls, head).

    Hands-on: Delete a file, and work with directories

    1. Delete backup.tsv, and check that it is gone:

      rm backup.tsv
ls

    2. Make a directory test, copy both data files into it, and list it:

      mkdir test
cp proteins.tsv proteins.fasta test/
ls test

    3. Make a second directory data, move the two files from test into it, and remove the now empty test with rmdir. The * is a wildcard: test/* means "every file in test". Before you use a wildcard, check what it matches with ls:

      mkdir data
ls test/*
mv test/* data/
ls test data
rmdir test

    Questions

    Q5. Now try to remove the directory data in the same way, with rmdir data. What happens, and why?

    Hands-on: Directories inside directories

    1. Make three directories inside each other in one command. -p tells mkdir to create the parent directories as well:

      mkdir -p nested/level2/level3

    2. Move data into the innermost directory, and list it there. Use Tab to complete the directory names instead of typing them in full:

      mv data nested/level2/level3/
ls nested/level2/level3/data

    3. Before you delete anything, look at everything inside nested with ls -R (recursive):

      ls -R nested

    Questions

    Q6. rm -r nested would delete nested and everything inside it. According to ls -R, which files and which directories would it delete?

    Hands-on: Delete the practice directories

    1. Delete nested with everything in it, and check what is left. Your two original data files in unix-practical are not affected:

      rm -r nested
ls

    Warning: rm -r

    rm -r deletes a directory and everything below it, at once and for good. Only use it on a directory you have just inspected, like here. Never combine it with a wildcard you have not checked. The temporary Galaxy environment does not make this safe: on your own computer or on a server, the same command deletes your real work.

    Part 3 — Look inside the files¶

    Hands-on: The protein table

    1. Show the first 10 lines of the table with head, then only the first 3 lines, and then the last 3 lines with tail:

      head proteins.tsv
head -n 3 proteins.tsv
tail -n 3 proteins.tsv

    2. Browse the whole table with less. Use the space bar to go down a page, b to go back, and type /DMD and Enter to search for the text DMD. Press q to quit less and get your prompt back:

      less proteins.tsv

    3. Count the lines, words and characters with wc, then only the lines with wc -l:

      wc proteins.tsv
wc -l proteins.tsv

    Questions

    Q7. What are the five columns of proteins.tsv? What does one line after the first one describe?

    Q8. How many proteins are described in proteins.tsv? Be careful: look again at what is on the first line.

    Hands-on: The FASTA file

    1. Show the first 4 lines of the FASTA file, and browse it with less (quit with q):

      head -n 4 proteins.fasta
less proteins.fasta

    2. Count its lines:

      wc -l proteins.fasta

    Questions

    Q9. A FASTA record starts with a header line that begins with >, followed by one or more lines of sequence. Look at the first header line. Which protein is it, from which organism, and what is its gene name? What is P02649?

    Q10. How many lines does proteins.fasta have? Can you tell from the number of lines how many sequences the file contains? Why, or why not?

    Note: FASTA and FASTQ

    In a FASTQ file (sequencing reads, see the NGS practical) every read takes exactly four lines: a header starting with @, the sequence, a + line and the quality line. There you can get the number of reads by dividing the number of lines by four. In a FASTA file you cannot.

    Part 4 — Columns, sorting and counting¶

    The table has a header line. Before you sort and count, make a copy without it. tail -n +2 prints a file from line 2 onwards, and > sends the output into a new file instead of to the screen.

    Hands-on: Remove the header

    1. Save the table without its header line, and check the new file:

      tail -n +2 proteins.tsv > proteins_data.tsv
head -n 3 proteins_data.tsv
wc -l proteins_data.tsv

    Note: Redirection with >

    Normally a command writes its output to the screen. command > file writes it into file instead. If file does not exist, it is created; if it exists, its old contents are replaced without warning. Never redirect into the file you are reading from: sort proteins_data.tsv > proteins_data.tsv leaves you with an empty file.

    Hands-on: Select columns with cut, and combine them with paste

    1. cut -f selects columns (fields) from a tab-separated file. Save the entry names (column 2) and the lengths (column 5) in two files:

      cut -f2 proteins_data.tsv > names.txt
cut -f5 proteins_data.tsv > lengths.txt
head -n 3 names.txt lengths.txt

    2. paste puts files side by side, line by line. Combine the two files, lengths first:

      paste lengths.txt names.txt > length_name.tsv
head -n 3 length_name.tsv

    Questions

    Q11. What does length_name.tsv contain, and in which order are the columns? Now run cut -f2,5 proteins_data.tsv (scroll up to see the first lines). In which order does cut print the two columns?

    Hands-on: Sort

    1. Sort length_name.tsv in two ways, and look at the last three lines of each result:

      sort length_name.tsv > sorted_text.tsv
tail -n 3 sorted_text.tsv
sort -n length_name.tsv > sorted_num.tsv
tail -n 3 sorted_num.tsv

    Questions

    Q12. Which three proteins in the table are the longest? The two sort commands disagree: which one gives the right answer, and why does the other one give a different result?

    Q13. Which protein in the table is the shortest? What is this protein?

    Hands-on: Ask the command for help

    1. Most commands describe their options when you add --help. Read the help of sort, scrolling up if necessary:

      sort --help

    Note: Getting help

    On most Unix systems man sort shows the full manual page. This Galaxy environment is a minimal system without manual pages: man only prints a message. Use --help here, or look up the command online (for example in the GNU Coreutils manual on the Resources page).

    Questions

    Q14. Which option makes sort reverse its order? Use it to write a command that lists the proteins in length_name.tsv from the longest to the shortest.

    Hands-on: Count identical lines with uniq

    1. Save the organism column, and count identical lines with uniq -c:

      cut -f4 proteins_data.tsv > organisms.txt
uniq -c organisms.txt

    2. Now sort the organisms first, and count again:

      sort organisms.txt > organisms_sorted.txt
uniq -c organisms_sorted.txt

    Questions

    Q15. How many different species are there in the table, and which species has the most entries? Why does uniq -c on the unsorted file give a different, much longer result?

    Part 5 — Search with grep¶

    grep prints the lines that contain a pattern. Put the pattern in single quotes, so that the shell passes spaces and special characters on to grep unchanged.

    Hands-on: Find lines

    1. Print the human entries, count them with -c, and save all the other lines with -v (invert):

      grep 'Homo sapiens' proteins_data.tsv
grep -c 'Homo sapiens' proteins_data.tsv
grep -v 'Homo sapiens' proteins_data.tsv > non_human.tsv
wc -l non_human.tsv

    Note: Patterns

    grep patterns are regular expressions. Most characters simply match themselves, but a few have a special meaning:

    Pattern Matches
    ^ the start of a line: ^> is a > at the start of a line
    $ the end of a line: SV=1$ is SV=1 at the end of a line
    . any single character
    [12] one character: 1 or 2

    The option -i ignores the difference between upper and lower case.

    Questions

    Q16. How many sequences are in proteins.fasta? Use grep, and remember what the first line of every FASTA record looks like. Does the number agree with the table?

    Q17. Count the p53 sequences with grep -c 'GN=TP53' proteins.fasta. Now look at the table: how many entries have an entry name starting with P53_? Why do the two numbers differ, and how do you make grep find all p53 sequences?

    Hands-on: Character classes

    1. Compare these two searches for BRCA1 and BRCA2 (the space after the pattern makes sure that longer gene names starting with the same letters are not matched):

      grep 'GN=BRCA[12] ' proteins.fasta
grep 'GN=BRCA. ' proteins.fasta

    Questions

    Q18. What do [12] and . mean in these two patterns? Do the two commands find the same lines here? How many BRCA1 and BRCA2 sequences are there in proteins.fasta if you also accept lower-case gene names?

    Part 6 — Save output: > and >>¶

    Hands-on: Collect lines from two searches in one file

    1. Save the human entries in a new file, then append the mouse entries to the same file with >>, and count the lines:

      grep '_HUMAN' proteins_data.tsv > selected.tsv
grep '_MOUSE' proteins_data.tsv >> selected.tsv
wc -l selected.tsv

    Questions

    Q19. How many lines does selected.tsv have, and where do they come from? What would the file contain if you had used > instead of >> in the second command?

    Part 7 — Pipes: connect commands¶

    In Part 4 you needed three commands and two extra files (organisms.txt, organisms_sorted.txt) to count the species. A pipe, written |, does this without files: it sends the output of the command on its left directly into the command on its right. You can chain as many commands as you like.

    Hands-on: First pipes

    1. Show only the first three FASTA header lines, and count the human entries by piping grep into wc -l:

      grep '^>' proteins.fasta | head -n 3
grep 'Homo sapiens' proteins_data.tsv | wc -l

    Questions

    Q20. Write the species count from Part 4 as one pipeline, starting from proteins_data.tsv and without any extra files. Add a last step so that the species with the most entries is at the bottom.

    Q21. Write one pipeline that prints the entry names and lengths of the three longest proteins, starting from proteins_data.tsv and without making any files. Hint: sort can sort on one column: -k2,2n sorts numerically on column 2.

    Part 8 — Challenge: a biological question¶

    The same gene in different species is called an ortholog. An entry name such as P53_HUMAN has two parts, separated by _: the protein (P53) and the species (HUMAN, MOUSE, RAT, …).

    How completely are the orthologs of these disease genes covered by reviewed Swiss-Prot entries? Answer the two questions below with pipelines you compose yourself. Start from proteins_data.tsv or from proteins.fasta, as you prefer.

    Tip: One new trick

    cut normally splits lines at tab characters. With -d you choose another separator: cut -d_ -f1 keeps the part of each line before the first _, and cut -d_ -f2 the part after it.

    Questions

    Q22. Which protein in the panel has a reviewed entry in the largest number of species, and in how many? Answer with one pipeline.

    Q23. CFTR is the gene mutated in cystic fibrosis. In how many species of the panel does proteins.fasta contain a CFTR sequence, and which species of the panel has none?

    Keep a record and finish¶

    Hands-on: Save your commands to your Galaxy history

    1. history lists the commands you typed in this terminal. Save the list in a file, and send the file to your Galaxy history with put, the partner of get:

      history > my_commands.txt
put -p my_commands.txt

      After a few seconds my_commands.txt appears in your Unix practical history, where it stays after the terminal is gone. You can send any other file the same way.

    2. When you are done, stop the Interactive Tool: Interactive Tools in the activity bar → the red square (Stop this interactive tool) next to JupyTool interactive tool. This deletes the temporary environment and frees the computer for others.

    Note: What next?

    The same commands work on any Unix system: macOS, Linux, or the compute servers where large sequencing projects are analysed, which you usually reach with ssh. Beyond this practical, sed and awk edit and compute on text, and shell scripts save a pipeline so that you can run it again on new data.

    Summary¶

    You opened a Unix shell in Galaxy Europe, found your way around the file system, and created, copied, moved and deleted files and directories. You inspected a protein table and a FASTA file, cut out columns, sorted text and numbers, counted identical lines, and searched with patterns. Finally, you connected small commands with pipes to answer biological questions without writing any intermediate files: the core idea of working on the command line.
